# CLI reference

All examples use an existing YAML file called CONFIG. Replace uppercase
placeholders with actual paths and returned IDs. CLI paths resolve from the
shell; YAML paths resolve from the configuration location. The
[installed help reference](api/cli-help.md) records every command's required
and optional arguments, generated by invoking each installed command with --help.

## Command contracts

| Command | Required inputs | Outputs and common errors |
| --- | --- | --- |
| version / doctor | None; doctor optionally --config and --probe | Version/runtime JSON. Readiness is not commissioning; live probe needs a backend. |
| config validate | --config YAML | Resolved config JSON; unknown keys or missing evidence fail. |
| fits inspect | INPUT; optional --config | Metadata manifest JSON; malformed/unsupported FITS fails. |
| camera characterize | SEQUENCE JSON, --config | Characterization JSON; needs a paired measurement manifest, not arbitrary images. |
| masters build | --config; paths or calibration_dir | Registry master and manifest/id. --kind selects type; --flat-dark (or --bias-reference) supplies flat reference. Mixed/incompatible sets fail. |
| masters list / inspect | --config; inspect also IDENTIFIER | Summaries or full manifest; missing ID fails. |
| calibrate / reduce | INPUT, --config | Product receipt with id/path/state. --dark/--bias and --flat select IDs; --dry-run plans; --revision labels reprocessing. reduce also runs QC/astrometry. Missing or ambiguous references fail. |
| qc | PRODUCT, --config | Fresh QC JSON; does not rewrite the product. |
| astrometry probe | --config; optional --backend | Launch/connection result; unavailable executable/service fails. |
| astrometry solve | INPUT, --config, --output NEW_DIR | Candidate WCS and validation.json. --verify requires independent VERIFIED status. |
| astrometry diagnose-raw | INPUT, --config, --output NEW_DIR | Raw-light extraction/solve diagnostics; --sources-only skips solving. |
| astrometry verify | INPUT, --config; optional --wcs/--solve-report | Verification JSON; unverified status returns nonzero. Does not upload images/centroids; Gaia retrieval follows explicit config network policy. |
| astrometry status | JOB_OR_RECEIPT_ID, --config | Saved/server status; --wait, --cancel, --attach and --abandon are mutually exclusive. |
| validate | PRODUCT | FITS/provenance validation JSON; corruption fails. |
| batch | --config; --input DIRECTORY, positional directory or raw_dir | Job/task summary. Supports --dark, --flat, --revision, --dry-run and backend policy. Failed/quarantined task counts return nonzero. |
| jobs list / inspect / retry | --config; inspect/retry also ID | Checkpoints or retry results; inspect --verify-products audits integrity. |
| benchmark | --dataset DIRECTORY | Ingestion timing JSON; no FITS fails. |
| report | Exactly one --product PRODUCT, --job ID or --latest | JSON; optional --html FILE. job/latest need --config. Missing/damaged evidence fails. |
| plots | --output NEW_DIR and diagnostic inputs | Figure file list; needs diagnostics extra. --master needs --config; --reference needs --product. |
| gaia-fetch | --wcs FILE, --height H, --width W, --midpoint UTC, --config | Catalogue path/query result; cache miss requires network opt-in. |

Normal success prints JSON to stdout and exits 0. Caught processing/configuration
errors print structured JSON to stderr and exit 1. Argument errors exit 2.
Scientific status is separate: exit 0 does not require COMPLETE or QC PASS.
astrometry solve requires --verify to make WCS acceptance mandatory for exit 0.
Batch task failures and report integrity failures also affect exit status.
See [first reduction](getting-started/first-reduction.md) for the complete workflow.

## Examples

| Task | Command |
| --- | --- |
| Inspect installed environment | `osp doctor` |
| Generate reproducible test data using the optional toolkit | `osp-sim generate --profile standard --seed 1234 --output example --adversarial` |
| Verify and report an exposure | `osp report --product PRODUCT --html exposure.html` |
| Verify and summarize a batch | `osp report --job JOB_ID --config CONFIG --html batch.html` |
| Plot scientific diagnostics | `osp plots --product PRODUCT --master ID --config CONFIG --output plots` |
| Cache a Gaia catalogue for a known WCS | `osp gaia-fetch --wcs WCS.fits --height H --width W --midpoint DATE --config CONFIG` |
| Authenticate to Nova without uploading | `osp doctor --config CONFIG --backend online --probe` |
| Test local ANSVR | `osp astrometry probe --config CONFIG --backend local` |
| Solve a raw light or calibrated product locally | `osp astrometry solve observation.fits --config CONFIG --backend local --output local-result` |
| Authorize a Nova centroid solve | `osp astrometry solve observation.fits --config CONFIG --backend online --allow-online --output nova-result` |
| Local-first solve with authorized fallback | `osp astrometry solve observation.fits --config CONFIG --backend auto --allow-online --output auto-result` |
| Inspect a Nova job or an OSP receipt | `osp astrometry status ID --config CONFIG` |
| Resume OSP polling | `osp astrometry status RECEIPT_ID --config CONFIG --wait` |
| Verify a candidate against Gaia | `osp astrometry verify observation.fits --wcs nova-result/candidate.wcs --solve-report nova-result/validation.json --config CONFIG` |
| Apply backend and permission to reduction | `osp reduce observation.fits --config CONFIG --astrometry-backend online --allow-online` |
| Queue a local-first batch | `osp batch --input observations --config CONFIG --astrometry-backend auto --allow-online` |

AUTO also requires `astrometry.fallback_enabled: true` before taking the
online branch. Image upload requires its separate flag or config permission.
Use `--verify` on `astrometry solve` to require scientific verification
for a successful exit status. Diagnostic JSON reports `solve_status` and
verification `status` separately. The receipt is independent of the
diagnostic output directory. See the [configuration reference](configuration.md).
